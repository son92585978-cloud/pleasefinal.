# Friends English Master RC1 — 사용·배포 안내

기준: 사용자가 올린 pleasefinal.-main.zip. 작성: 2026-11-17 (시드니).

## 먼저 확인

이 파일은 기존 앱에 통합한 **검수 후보판(RC1)**입니다. 완성판이나 236화 대본·음성 패키지가 아닙니다. 공식 클립 4개 링크와 개인 자료 학습 엔진을 연결했습니다. 배포 권한이 확보된 내장 프렌즈 정답 문장은 0개입니다. 실제 모바일/PWA 설치/외부 미디어 재생은 미검증입니다.

## 사용 방법

1. 시작 페이지의 기존 단어 학습 기능을 그대로 이용합니다. 상단 **🎧 Friends**로 대화 학습에 들어갑니다.
2. **시즌 탐색 → Season 1 → Episode 1 또는 Episode 3**에서 공식 클립을 고릅니다.
3. 플레이어 연결 버튼을 누르면 YouTube에 연결합니다. 플레이어 안의 재생 버튼을 누르세요. 영상은 공식 플레이어 형태로 표시되며 음성만 분리하거나 플레이어를 숨기지 않습니다.
4. 시작/종료 초를 입력해 구간을 지정합니다. 종료 0은 전체 재생입니다. 실제 구간 제어와 속도 지원은 외부 플레이어가 정상 연결되었을 때만 활성화됩니다. 타임코드는 검수된 대사 위치가 아니라 사용자가 정하는 값입니다.
5. 자유 받아쓰기는 자동 저장되지만 정답 대본이 없어 자동 채점하지 않습니다. 구간 지정 후에도 재생 제한이 있으면 공식 YouTube 링크를 이용하세요.
6. 사용 권한 있는 자막과 미디어가 있다면 **자료·설정**에서 시즌/화, 출처, 권한 근거를 입력하고 확인란을 체크해 SRT/VTT를 추가합니다. 해당 에피소드 → 장면 → 문장에서 원본 미디어를 연결합니다. 미디어는 기기의 IndexedDB에 저장하며 서버로 보내지 않습니다.
7. 자막만 추가하면 해석·문법·IPA는 자동 생성하지 않고 미등록으로 표시합니다. 설명이 완성된 JSON 학습팩을 추가하면 문장 해석과 표현 상세가 표시됩니다. 잘못된 권리 표시는 앱이 인증하지 않습니다.
8. 채점은 대소문자·일반 문장부호·스마트 아포스트로피를 정규화합니다. 단어 편집 거리로 정답률을 계산하며 누락/추가/다른 단어/순서 이동을 표시합니다. 축약형을 풀어 쓴 답은 동일 답으로 처리하지 않습니다. `I'm`과 `I am`은 다르게 채점됩니다.
9. 정답 공개 후 표현을 누르면 상세 설명을 열 수 있습니다. 이전 버튼과 브라우저 뒤로가기는 입력·공개 상태를 보존하도록 구현했습니다. Android 하드웨어 뒤로가기는 실기기 확인이 필요합니다.

## 업데이트 전 데이터 백업

- 같은 주소·브라우저에 배포하면 기존 `travelWork331:` 저장 키를 그대로 사용합니다. 기존 오답, 사용자 단어, 연상 수정, 음성 설정을 초기화하지 않습니다.
- 신규 Friends 화면 → 자료·설정 → **학습 데이터 백업 내려받기**로 JSON을 저장합니다. 기존 대화의 저장 키도 보존·백업하지만 Friends 목록에는 노출하지 않습니다.
- 주소나 기기를 바꾸면 자동 이전되지 않습니다. 새 주소에서 백업 복구를 사용하세요. 복구는 포함된 키를 덮어씁니다.
- 미디어 파일과 AI 접속 토큰·엔드포인트는 백업에서 제외합니다. 미디어는 별도로 보관하고, 새 기기에서는 다시 연결합니다.
- 원본 ZIP 백업에는 브라우저에만 저장된 개인 학습 기록이 들어 있지 않습니다.

## ZIP의 시작 위치

완성 ZIP을 압축 해제했을 때 **index.html이 있는 폴더**가 배포 루트입니다. ZIP 안의 파일을 수정할 필요는 없습니다. `audio`, `neural`, JavaScript, manifest, sw.js를 함께 올려야 합니다. 예전 듣기 데모가 덮어쓴 index.html을 기존 단어 앱으로 복구했습니다.

## Netlify — 처음 배포

1. PC에서 ZIP을 다운로드하고 압축을 풉니다.
2. Netlify에 로그인하고 https://app.netlify.com/drop 을 엽니다.
3. **index.html이 바로 들어 있는 폴더 전체**를 드래그합니다. 폴더를 선택하면 index.html이 보여야 하며, 그 바깥 부모 폴더를 올리지 않습니다.
4. 제공된 HTTPS 주소를 열고 기존 단어 화면과 Friends 버튼을 확인합니다. 빌드 명령은 필요하지 않습니다.
5. 이 앱은 기존 음성·모델·설명 파일을 보존해 용량이 큽니다. Netlify는 작은 수동 배포를 권장하므로 업로드가 오래 걸리거나 멈추면 GitHub 저장소를 연결하는 방식이 적합합니다. 임의로 audio 폴더를 빼지 마세요.

## Netlify — 기존 주소 업데이트

1. Netlify 대시보드에서 **현재 쓰는 프로젝트**를 선택합니다.
2. **Deploys**의 수동 배포 영역에 압축 해제한 폴더를 올립니다.
3. 새 프로젝트를 만들지 않으면 기존 주소를 유지할 수 있습니다. 성공 상태를 확인한 뒤 기존 주소에서 새로고침합니다.
4. 홈 화면 앱을 완전히 닫았다 다시 열고, 상단에 **Friends 통합 RC1**이 표시되는지 확인합니다. 데이터 보존을 위해 브라우저 사이트 데이터를 지우지 마세요.

## GitHub Pages — 기존 저장소 업데이트

1. 기존 사이트의 저장소를 엽니다. 먼저 `index.html`이 있는 위치를 확인합니다.
2. **Add file → Upload files**에서 압축 해제한 파일과 폴더를 같은 위치에 올립니다. ZIP 파일 자체만 올리면 앱이 배포되지 않습니다.
3. 브라우저 업로드는 한 번에 100개 파일, 파일당 25 MiB 제한이 있습니다. 파일 수가 많으면 여러 번 나누어 올리거나 GitHub Desktop의 저장소 폴더에 복사 후 Commit/Push합니다. 이 패키지는 단일 파일 25 MiB 미만입니다.
4. **Settings → Pages → Build and deployment**에서 **Deploy from a branch**, 배포 브랜치(예: main), **/(root)**를 선택합니다. 기존 프로젝트가 `/docs`를 사용하면 그 폴더에 파일을 넣고 기존 설정을 유지합니다.
5. Actions 또는 Pages 상태에서 배포 성공을 확인하고 HTTPS 주소를 엽니다. `.nojekyll`을 포함합니다.
6. GitHub Pages의 `/저장소명/` 경로를 고려해 상대경로를 사용합니다. 사이트를 다른 이름으로 옮기기 전 데이터 백업을 하세요.

## 홈 화면 설치·오프라인

- Android Chrome: HTTPS 사이트 열기 → 메뉴 → 앱 설치 또는 홈 화면에 추가. iPhone Safari: 공유 → 홈 화면에 추가. 실제 메뉴는 기기와 브라우저에 따라 다릅니다.
- manifest에는 192/512 PNG 아이콘과 상대 start_url/scope가 있습니다. 실기기 설치는 아직 미검증입니다.
- 온라인 최초 접속 후 핵심 화면·자료 파일을 캐시에 저장하도록 구성했습니다. 최초 연결과 캐시 준비 전에는 오프라인 실행이 보장되지 않습니다.
- 단어 음성은 사용한 묶음을 캐시합니다. 모든 음성 파일을 최초 설치 때 저장하지 않습니다. 사용자 미디어는 브라우저 저장 용량의 영향을 받습니다.
- 공식 YouTube 재생은 항상 인터넷이 필요합니다. 오프라인에서는 배우 음성이 있다고 표시하지 않습니다.

## 이후 시즌·자료 추가

시즌별 화수는 24, 24, 25, 24, 24, 25, 24, 24, 24, 18입니다. 합쳐 방영한 회차도 분리하는 236화 번호 체계이며, 플랫폼이 합본으로 표시하면 타임코드를 따로 확인해야 합니다.

개인 학습 자료는 코딩 없이 SRT/VTT를 추가할 수 있습니다. 설명을 갖춘 학습팩은 아래 스키마로 콘텐츠 담당자가 JSON을 제작해 **자료·설정 → 학습팩 JSON**으로 불러옵니다. 가져온 데이터는 해당 브라우저에만 저장되고 배포 ZIP에 자동 포함되지 않습니다. 공개 배포를 하려면 별도의 권한 확인과 소스 반영이 필요합니다.

### 학습팩 스키마

아래는 실제 대사가 없는 구조 안내입니다. `사용 허가된 원문` 등을 확인된 콘텐츠로 바꾸고 시간·offset을 정확히 작성하세요. `id`는 영문/숫자/_/-만 사용하며 팩은 `user-`로 시작합니다. 같은 ID를 다시 가져오면 진도 충돌을 막기 위해 거절합니다.

```json
{
  "version": 1,
  "series": "Friends",
  "id": "user-my-s01e01",
  "episodeId": "s01e01",
  "title": "자료 제목",
  "rights": {"confirmed": true, "source": "확인된 출처", "basis": "확인된 허가 근거"},
  "media": {"kind": "local"},
  "scenes": [{
    "id": "scene-01", "title": "확인된 장면 제목",
    "dialogues": [{"id": "dialogue-01", "title": "대화 제목", "sentences": [{
      "id": "sentence-01", "speaker": "확인된 화자",
      "start": 0, "end": 3,
      "text": "사용 허가된 원문",
      "analysis": {
        "ko": "자연스러운 한국어 해석",
        "structure": "주어 / 동사 / 목적어 / 보어 / 수식어 분석",
        "chunks": [{"en": "의미 단위", "ko": "분해 해석"}],
        "context": "확인된 발화자·청자·상황·의도",
        "nuance": "전체 문장의 의미와 뉘앙스",
        "grammar": [{"title": "시제를 선택한 이유", "body": "문맥과 대체 표현의 차이"}]
      },
      "terms": []
    }]}]
  }]
}
```

`terms`의 각 항목: `offset`(문장 내 0부터 시작하는 문자 위치), `text`(묶음 클릭할 원문), `lemma`, `pos`, `ipa`, `pron`, `forms`, `meaning`, `reason`, `comparison`, `mnemonic`, `examples`(각각 en/ko/note를 포함한 예문 3개). 구동사·관용구는 하나의 text로 묶습니다. offset과 실제 원문이 어긋나거나 클릭 범위가 겹치면 가져오기를 거절합니다. IPA와 활용형이 해당하지 않으면 이유를 적고, 미확인 정보를 추정해 채우지 않습니다.

문법 설명에는 문장에 해당하는 시제, 조동사, 전치사, 구동사, 의문문 어순, 주어·목적어, 생략·축약, 미국식 용법, 비슷한 표현 차이, 어색한 대체 표현을 각각 넣습니다. 해당하지 않는 항목은 근거와 함께 생략 가능합니다. 예문은 독자적으로 작성하고 방송 대사로 표시하지 않습니다.
